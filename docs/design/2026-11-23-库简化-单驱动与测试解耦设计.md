# timewheel 库简化：单驱动 + 删 legacy + 测试与 Redis 解耦

日期：2026-11-23
状态：待用户批准
前置：基于已合并 master 的 at-least-once 实现（PR #3）做减法，不回退语义。

## 1. 背景与用户裁定

用户对当前复杂度提出两点批评，并做了三项裁定：

1. 测试不应绑定 Redis 驱动/真实实例 → 测试金字塔改造（§5）。
2. 项目过重（产品 795→1532 行、测试 139→1886 行、Lua 3→12 个）→ 瘦身。
3. 裁定：**无存量部署，legacy 升级机制整块删除**；**只保留 go-redis 驱动**；
   **保留 at-least-once 语义**（ACK/重试/死信/租约回收）。

依赖目标随之简化为：单 module、go.mod 直接依赖 `gocast + redis/go-redis/v9`，
redigo 彻底移出。此前嵌套 module 方案作废（草案已删）。

## 2. 删除清单

**legacy 升级机制**（无存量，迁移辅助无对象）：

- 引擎：`bootstrapLegacyShards()`、启动 goroutine；
- 脚本与调用层：`ScanStepLuaScript`、`RegisterMinuteLuaScript`、`scanStep()`、`registerMinute()`；
- claim 脚本中的旧成员分支（`{` 开头 → cjson 解码、秒级 score 视为立即到期）；
  信封 codec 的 `Legacy` 字段与分支；
- tick 中"当前分钟无条件扫描"——其存在理由是覆盖未登记 registry 的旧版写入；
  AddTask 与 recover 都在同一 Lua 内原子写 pending+registry，无旧版写入后该保护
  失去对象（详见 §4 裁量 2）；
- 测试：`TestLegacyShardDiscovery`、`TestLegacyMemberUpgrade`、`pushRaw` 中仅服务于
  legacy 的用法；
- 文档：README 升级章节。

**redigo 驱动**：

- `pkg/redis/redigo/` 整目录；
- 测试侧 `testStores()` 双驱动循环，测试只构造 goredis store；
- README 中 redigo 相关内容。

**死代码**（零调用/零读取）：

- `Store.SAdd` 接口方法及 goredis 实现（库代码零调用）；
- `ClientOptions.DB` 与 `WithDB`（适配器不读取，静默连 DB 0 的陷阱选项）。

## 3. 保留清单（不动语义）

- 信封 v1（attempt/claimID）、claim/ack/fail/dead/recover 五脚本；
- 分钟分片 + registry（用户明确的大任务量/减压设计）；
- 引擎单 goroutine tick、有界领取、handler 超时、panic 计失败、ack 重试；
- `Shutdown` 语义与顺序、`RemoveTask` delset、退避与死信保留配置；
- Redis 5.0 命令基线不变。

## 4. 我的裁量（可否决）

1. **删 stats、留 resultHook**：`StatsLuaScript`、`Stats` 类型、`WithStatsInterval`、
   `maybeStats`/`claimLag` 全删；`WithResultHook`（success/retry/dead_lettered/removed/
   ack_failed 事件）保留——死信告警等消费场景真实存在，stats 快照没有点名需求。
   若要留 stats 说一声。
2. **删"当前分钟无条件扫描"**：依据 §2 的原子性论证（AddTask/recover 同脚本原子登记
   registry；claim 清空分片时原子 ZREM）。若担心极端场景丢失 registry 入口，可保留
   该保护，代价是每 tick 一次额外 EVAL。
3. `redis_scripts_test.go` 等 L3 用例中仅服务于双驱动差异断言的部分随单驱动化简化。

## 5. 测试金字塔（核心改造）

现状问题：31 个用例几乎全部需要真实 Redis + 具体驱动，引擎逻辑与基础设施绑死。

目标结构：

- **L1 纯单测（无 Redis，已有+保留）**：信封 codec、options 校验、退避计算、minuteOf。
- **L2 fake Store 引擎测试（新增主体）**：`redis.Store` 只有 `Eval` 一个核心方法
  （SAdd 删除后）；测试内实现 fake——按脚本常量分发，返回各用例编排好的应答，
  并记录调用序列。覆盖：结算分支（成功/重试/死信边界 attempt==maxAttempts）、
  panic 转失败、ack 网络错误重试与 ack_failed、领取限流（maxConcurrency-inflight）、
  Shutdown 等待顺序、hook 事件发射。无网络、确定性、微秒级。
- **L3 真 Redis 集成（保留瘦身）**：Lua 语义（zset/score/原子性/租约回收）与端到端
  （执行时机、崩溃恢复、RemoveTask、不早于 executeAt）。单驱动单包单二进制，
  顺序执行——`-p 1` 之类的并行规避不再需要。

**保真度声明（诚实的代价）**：fake 只模仿应答形状，与真实 Lua 的漂移会产生假绿灯，
因此 L3 是 Lua 真值的唯一裁判，不可删。L2 测的是引擎对"脚本成功/失败/返回什么"的
反应，这个责任边界写进 L2 文件头注释。

## 6. 结构与依赖结果

```
github.com/dej4vu/timewheel          单 module
├── go.mod                           gocast + redis/go-redis/v9（+ indirect）
├── pkg/redis/                       Store（仅 Eval）+ option（去 DB）+ script.go + lua/
├── pkg/redis/goredis/               唯一适配器（去 SAdd）
├── examples/redis/                  原地不动（同 module，无依赖问题）
└── 根包                             引擎 + L1/L2/L3 测试
```

无 go.work、无嵌套 module、无多发版 tag。发布仍是单 tag。

## 7. 验证计划

1. `go test -race ./...` 连续 3 次绿（Redis 可达时含 L3；不可达时 L3 skip、L1/L2 全跑）。
2. L2 引擎测试在无 Redis 环境可独立运行并全绿（验证解耦目标达成）。
3. `gofmt -l` 空、`go vet ./...` 干净。
4. go.mod 断言：不含 `gomodule/redigo`。

## 8. 非目标

- 不改 at-least-once 语义与 Redis 5.0 基线；
- 不重设计分片/registry；
- 不引入 CI、不加新依赖。
