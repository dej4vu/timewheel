# timewheel 库简化实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留 at-least-once 语义的前提下给库做减法：删 redigo（单驱动 go-redis）、删 legacy 升级机制、删 stats 观测面与死代码，并把引擎测试改为 fake Store 驱动（与真实 Redis 解耦）。

**Architecture:** 纯删除 + 测试金字塔改造。产品代码只删不加；引擎行为仅有一处变化（tick 改为纯 registry 驱动，删无条件当前分钟扫描），先写 RED 测试固化。L2 fake Store 测试与 L3 真 Redis 集成的责任边界：L2 裁决引擎控制流，L3 是 Lua 语义的唯一裁判。

**Tech Stack:** Go 1.23、redis/go-redis/v9、Lua（Redis 5.0 基线）、标准库 testing。

**Spec:** `docs/design/2026-11-23-库简化-单驱动与测试解耦设计.md`

## Global Constraints

- 单 module；完成后 go.mod 直接依赖仅 `github.com/demdxx/gocast` + `github.com/redis/go-redis/v9`（+ indirect），不得出现 `gomodule/redigo`。
- Redis 5.0 命令基线与 Lua 5.1 约束不变：分隔符十进制 `"\31"`、`unpack` 每批 ≤500、`TIME` 效果复制。
- at-least-once 语义不变：ACK/重试/死信/租约回收/Shutdown 的既有测试（PR #3）必须全程保持绿。
- 每个任务提交前 `go test -race -count=1 ./...` 绿（Redis 不可达时集成用例按既有语义 skip）。
- Git：身份用已配置的 `dej4vu <origineme@gmail.com>`；提交信息以 `Co-Authored-By: Claude Code <noreply@anthropic.com>` 结尾；禁用 `git stash`；所有操作留在本 worktree。
- 行为变化的步骤必须先有 RED 测试；纯删除步骤以"全量测试绿 + 符号 grep 为空"为验证。

## Review Focus

1. **fake 应答与真实 Lua 漂移 → L2 假绿灯**：L2 的 claim 应答必须用 `encodeEnvelope` 构造（与生产同源），且 L3 集成用例一个不删（Task 5 步骤 2 与 Task 6 步骤 3 钉死）。
2. **删无条件扫描后，未登记 registry 的写入会静默滞留**：`TestUnregisteredShardNotScanned` 固化"无 registry 条目即不领取"不变式（Task 3）。
3. **删 legacy 后 `{`-JSON 成员应进死信而非执行**：`TestDecodeRejectsLegacyJSON` + 既有 `TestClaimMalformedToDead` 保持绿（Task 3）。
4. **删 stats 误伤 resultHook 事件流**：`TestAckFailureReportsOutcome` 与 `TestRetryWithBackoff` 的 hook 断言全程绿（Task 4）。
5. **tick 改纯 registry 驱动后分钟边界任务丢失**：`TestBacklogAcrossMinutes`、`Test_NotEarlierThanExecuteAt` 全量回跑（Task 3 步骤 9）。
